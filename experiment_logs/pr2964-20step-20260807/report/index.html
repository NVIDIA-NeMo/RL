Preparation and failure chronology

  1. Source and controls locked

    Validation source a028b33b contains PR #2964 60a10b4f and the x86 HybridEP dependency a9aaa395. Both recipes retain their canonical batching and parallelism.

  2. Configuration and environment checks prepared

    validate_configs.sbatch, inspect_frozen_envs.sbatch, and probe_hybridep_b200.sbatch cover Hydra values, actor interpreters, and the failure mode where DeepEP is absent from an image environment.

  3. SM100 HybridEP wheel prepared

    build_hybridep_17cf_b200.sbatch builds and import-checks DeepEP 17cfb817. Launchers verify SHA256 82487725…e5f99 before installing its node-local overlay.

  4. Nightly image staging retried

    Registry import job 504915 was superseded because a layer containing over one million tiny files could not be extracted within the staging walltime. CW upload 15336366 completed, followed by GCP download 505067 and full SHA gate 505085.

  5. Smoke gate passed

    Job 505087 completed successfully and validated Python 3.13.14, vLLM 0.25.1, a visible B200 GPU, and all three DeepEP/HybridEP imports in both frozen actor environments.

  6. Training validations submitted behind the smoke

    Qwen attempt 505090 failed before step 0 during vLLM CUDA-graph warmup when one worker on pool0-0167 exited. Retry 505121 preserved the recipe, excluded that node, and completed all 20 steps plus Step 20 validation with Slurm exit 0:0.

  7. Super vLLM initialization isolated

    Super attempt 505091 failed on multiple TP=8 groups at custom_all_reduce.cuh:455. Attempt 505208 disabled that transport and exposed a FlashInfer TRTLLM MoE compiled-GEMM illegal access during CUDA-graph profiling. Attempt 505245 selected Triton MoE but retained CUDA graphs and hit the same compiled-GEMM path.

  8. Super reached HybridEP and exposed the blocking failure

    Attempt 505265 additionally enabled eager vLLM execution. All rollout engines and 256 Megatron policy ranks initialized; Step 1 generation, rewards, and advantage computation completed. At reference logprob, HybridEP entered the EP=32 inter-node path and all ranks segfaulted in RDMACoordinator::allocate_combine_buffers(). No Step 1 metric was completed.

  9. Alternative backend availability checked

    The exact 17cfb817 wheel was built with its default DOCA backend. That commit offers an experimental NIXL backend only when built with USE_NIXL=1; it also requires NIXL/UCX/etcd development inputs and an etcd endpoint reachable by every node. Probes 505327 and 505334 found NIXL 1.3 pip wheels with bundled NIXL, UCX, and etcd-client shared libraries, but no nixl.h, coherent NIXL_HOME development prefix, NIXL pkg-config entry, or etcd server executable. The current nightly is therefore not sufficient for the documented NIXL source build and runtime.

  10. Inter-node failure reproduced independently of NeMo RL

    Jobs 505516 and 505517 constructed only HybridEPBuffer across four B200 nodes. Both the requested 17cfb817 wheel and newer f725d296 wheel segfaulted before dispatch, so NeMo RL padding, reward computation, and model weights are outside the failure boundary.

  11. Legacy MR failure measured

    Job 505626 intercepted the versioned ibv_reg_mr_iova2@IBVERBS_1.8 call. All twelve combine-buffer registrations across two ranks returned NULL with EFAULT; DeepEP then dereferenced the null MR. Job 505651 confirmed the node has active RoCE HCAs and accessible uverbs devices but no loaded nvidia_peermem module.

  12. DMA-BUF fallback feasibility passed

    Job 505660 exported a 16 MiB CUDA allocation with cuMemGetHandleForAddressRange and registered it on rocep145s0 with ibv_reg_dmabuf_mr. The result was non-null with errno=0, proving a software fallback is available on the same nightly and hardware.

  13. Guarded fallback built and validated

    Job 505698 built the exact requested DeepEP base 17cfb817 with a helper that preserves the legacy ibv_reg_mr fast path and falls back only after registration failure. Jobs 505700 and 505713 passed the inter-node buffer-construction test at 2 × 1 GPU and 4 × 8 GPUs, respectively.

  14. Canonical model validation resumed

    Jobs 505735 and 505736 use the repository performance recipes with 20 steps and explicit HybridEP topology. Qwen completed all 20 steps with Slurm exit 0:0. Super completed all 256 vLLM and policy-worker initializations plus Step 1 generation, rewards, and advantages.

  15. Super exposed a traffic-time RDMA completion failure

    At the first reference-logprob dispatch, all ranks selected the DMA-BUF fallback and began inter-node traffic. The DOCA dispatch kernel then failed at hybrid_ep_backend.cuh:1187 because doca_gpu_dev_verbs_poll_cq() returned a negative status. The later Transformer Engine grouped-GEMM launch errors were downstream symptoms of the device-side assertion. Job 505736 was cancelled only after the driver was terminal, avoiding 256 idle GPUs.

  16. Minimal transfer reproduction isolated WQE 0

    Job 505820 used two nodes and one GPU per node, forced every token to an expert on the other node, and reproduced the same dispatch assertion without model weights. Job 505831 enabled CQ diagnostics and observed syndrome 0x05 on the final WQE, meaning it was flushed by an earlier failure. Job 505845 polled completions sequentially and identified WQE 0 with syndrome 0x04, which Linux mlx5 maps to IB_WC_LOC_PROT_ERR.

  17. Registration hypotheses rejected cheaply

    Jobs 505979 and 506063 showed why the constructor-only fallback was insufficient. DeepEP cudaMalloc pointers can be non-page-aligned, and a DMA-BUF MR base is not necessarily the application buffer base. Using mr->addr as the token pointer therefore changed the address encoded in the first WQE.

  18. Original CUDA address preserved

    Fix a9d657d2 registers the page-aligned DMA-BUF span for its lkey/rkey but stores the original allocation pointers in dispatch/combine memory-region metadata and remote address exchange. This is a no-op for the legacy path, where the MR and CUDA addresses already match.

  19. Actual inter-node traffic passed

    Job 506083 forced 128 tokens to experts on the other B200 node with probabilities enabled. Both ranks used the DMA-BUF fallback; buffer creation, dispatch, and combine completed before Slurm exit 0:0. Canonical 32 × 8 Super retry 506100 then passed full 256-rank reference logprob, proving the RDMA fix at workload scale.

  20. Super exposed and verified a separate MCore mask bug

    During activation recomputation, official MCore applied a flattened token mask directly to a two-dimensional expert routing map. This failed only when gradients and Super's expert-bias bookkeeping were active. Regression job 506260 reproduced the shape mismatch; fix 340af84f broadcasts the mask over the expert axis, and job 506272 passed the focused 8-GPU test. Canonical fixed retry 506276 is running.

W&B is configured in offline mode by both launchers. Local Slurm, Ray, training, and TensorBoard artifacts are therefore the authoritative result sources. Current MCore keeps original and padded HybridEP token counts internally but does not log them; THD sequence-packing efficiency is distinct and will not be presented as HybridEP dispatch-padding overhead.
Qwen job 505735 correctness sanity: all 20 steps completed; Steps 2–20 have finite loss and reward with means 0.0033 and 0.5250, respectively. Final validation accuracy is 0.5312. These checks establish execution stability but do not by themselves prove zero numerical regression against a controlled baseline.
Current conclusion: PR #2964 still supplies the NeMo RL side of the THD contract: it enables MCore's unequal-rank input padding, creates the physical THD padding mask, and aligns that mask with the model's sequence-parallel layout. MCore PR #5008 equalizes dispatcher input sizes and rounds them to 64 tokens. Two independent downstream bugs blocked Super: DeepEP's first DMA-BUF fallback conflated MR base and CUDA buffer base, and MCore applied a flattened token mask without an expert-axis broadcast during expert-bias recomputation. The former is fixed by a9d657d2; the latter is fixed and unit-tested by 340af84f. Neither failure shows that the earlier NeMo RL padding patch was ineffective. End-to-end Super correctness and performance are now under validation in baseline 506123 and fixed HybridEP 506276.
