## 2026-09-01 — Fixes for the two compaction "surprises" + rollout debug persistence

**nv-opencode (clone at `/home/geshen/compaction/nv-opencode`, branch `sdd/compaction-segments`, uncommitted):**
- `packages/opencode/src/provider/sdk/nemo-gym/language-model.ts`: the wire token-ID attach rule is now segment-aware. The segment for the call being built is computed up front (`_peekSegment`/`_currentSegment`, non-mutating twin of `_nextSegment`, which still commits in `_dumpAndNotify` with a mismatch warning), every turn's provider metadata is stamped with `segment_index`, and IDs are attached only when `md.segment_index === currentSegment` (`_idsBelongToCurrentSegment`; metadata without a stamp keeps the old compaction-turn-only guard). Effects: (a) a retained pre-compaction tail can no longer re-attach old IDs and undo compaction (latent death spiral, B4); (b) the compaction summarization call attaches nothing, so the model finally sees the compaction prompt with truncated tool outputs instead of the spliced original stream (B3).
- `packages/opencode/src/session/compaction.ts`: `estimate()` strips `providerOptions` from model messages before `Token.estimate(JSON.stringify(...))`, so token-ID arrays no longer inflate the tail size and `select()` retains the intended ≤ `preserve_recent_tokens` tail (surprise 1). Order matters: this must not ship without the wire-rule change above.
- Hardening (after peer review): unstamped token-ID metadata is attached only while the session is still in segment 0; once any compaction happened, an unstamped assistant may be a retained pre-compaction tail and is never attached (`_idsBelongToCurrentSegment`).
- Summary validation with retry (`compaction.ts processCompaction`): after the summary call returns, the stored summary is rejected if empty, if it carries tool parts, or if its text contains `<tool_call>`/`</tool_call>`/`<function_call>`/`</function_call>`. A rejected attempt is marked errored (so `completedCompactions`/`filterCompacted` skip it and `toModelMessages` drops it) and the summary call is re-run with a fresh assistant message, up to 2 retries; if every attempt fails the last one is kept (no session stop) and a warning is logged. Each attempt is its own `x-turn-kind: compaction` call and therefore its own dumped segment (bad attempts train with the −5 override, the accepted one with the rollout advantage); `post_compaction` still fires exactly once on the next ordinary call because `pendingSegmentBoundary` is a flag, not a counter. `message-v2.ts filterCompacted` now requires `finish && !error` when picking the summary anchor, matching `completedCompactions`. Tests: two new cases in `test/session/compaction.test.ts` (tool-call string then valid summary → 2 attempts, first errored, only the second visible via `filterCompacted`; three invalid replies → last kept, result "continue").
- nemo-rl `grpo.py` penalize_invalid_tool_call loop now also emits `penalty/invalid_tool_call/{msg_count,rollout_fraction}` and `penalty/invalid_tool_call/by_segment_kind/{compaction,other}_msg_count` using the plumbed `trace_metadata`. No exemption for compaction traces (would be a `grpo.*` flag defaulting to false if ever wanted). Further compaction metrics are being added by another session on branch `sdd/swe-opencode-superv35-compaction-metrics`; this branch (`sdd/swe-opencode-superv35-compaction-debug`, worktree `.claude/worktrees/compaction-fixes`) is the base it rebases onto. ## 2026-09-01 — Review of the `scripts/super_v35_swe_compaction.sh` compaction codepath

**What was done.** Read-only review of the full path launch script → `grpo_ultra_swe_e2e_opencode_compaction.yaml` → Gym `swe_agents/app.py` → nv-opencode fork (`sdd/compaction-segments`, cloned at `/home/geshen/compaction/nv-opencode`) → `nemo_rl/environments/nemo_gym.py` → `nemo_rl/experience/rollouts.py` → `nemo_rl/algorithms/grpo.py` async loop → `loss_functions.py`. One reviewer per layer, each bug/risk finding checked by two adversarial verifiers, then re-read by hand. No files outside `analysis/compaction/` and this log were modified.

**Artifact.** `analysis/compaction/compaction_codepath.html` — mechanics walkthrough (trigger math, summary call, segments → traces → advantage), ranked findings, existing metrics to plot, metrics to add with insertion points, ranked reward-drop hypotheses.

**Key facts established (with pointers).**
- Compaction fires when the last turn's `prompt_tokens + completion_tokens >= context − maxOutputTokens` = 131072 − 32768 ≈ 98k (`overflow.ts:8-26`, `bench/cli.ts:213-215`). `OPENCODE_CONTEXT_LIMIT_TOKENS=131072` in the launch script is a no-op (identical to the fork default). Requests carry no `max_tokens` (`language-model.ts:536-541`).
- No verbatim tail survives compaction in this run: `compaction.select` sizes the tail with `Token.estimate(JSON.stringify(toModelMessages(...)))`, and the model messages include every assistant's token-ID arrays in `providerOptions`, so the 8k budget is never met. Post-compaction context = system + "What did we do so far?" + summary + "Continue…".
- The compaction summary call attaches the head's last assistant's token IDs, so the vLLM proxy (`vllm_worker_async.py:499-637`) rebuilds the ORIGINAL prefix: the model sees the SWE system prompt with tool definitions and untruncated history, never the compaction agent prompt; with no `tools` in the request a tool call becomes text, is stored as the summary, and gets the −5 invalid-tool-call override.
- Loss is REINFORCE + truncated IS, not PPO: `force_on_policy_ratio: true` makes the ratio identically 1 (`loss_functions.py:366-371`); per-token weight = `A × clamp(exp(logp_train − logp_vllm), 0.2, 5)`; whole variable-size trace batch is one optimizer step (`grpo.py:6009-6024`).
- `agent_max_turns: 300` is per segment (`prompt.ts:1487-1488`); with compaction the only rollout-wide bound is the 3600 s wall clock, whose timeout skips eval (reward 0 even with a good patch) and masks the rollout. Masked rewards stay in the LOO baseline (`advantage_estimator.py:72-77` hard-codes `valid_mask=ones`) with zero gradient.
- `grpo.penalize_malformed_thinking` / `malformed_thinking_advantage` / `env.nemo_gym.thinking_tags` are dead config (consumer removed in f57f6adc4). Only `penalize_invalid_tool_call` (−5 per-message advantage override, `grpo.py:5988-6000`) is live. `apply_reward_penalties` is fully dormant (all four root flags false).
- Replay-buffer trajectory version is stamped at spawn (`async_utils.py:960,1020`), target = v+1, so `avg_trajectory_age` is identically 1. Refit never drains or resets KV (`recompute_kv_cache_after_weight_updates: false`; validation never runs).
- `seq_logprob_error_threshold: 2` gates each trace on the arithmetic mean of `exp|Δ|` (`grpo.py:3395-3398`); one token with |Δ| > ln(N+1) masks the whole trace.
- Gym auto-logs every scalar field of the verify response as `swe_agents_train/<field>/mean` (`rollouts.py:1568-1582`): `agent_timed_out`, `patch_exists`, `resolved`, `oom_killed`, `eval_timed_out`, `openhands_run_time`, …. `agent_error_kind` (str) and `mask_sample` (nested) are NOT logged. Per-trace segment metadata is produced by Gym (`app.py:3934-3939`) but dropped in `nemo_gym.py:288-294`.

**Bugs found.** (1) `${LR}` undefined → `set -u` abort before sbatch (`super_v35_swe_compaction.sh:561`). (2) Dead malformed-thinking penalty config. (3) Compaction call does not see the compaction prompt (above). (4) Latent tail re-attachment death spiral (blocked today only by the estimator quirk). (5) Tool-call-only turns with null content carry no token IDs → older IDs attached → intermediate turn silently spliced out of the effective prompt.
