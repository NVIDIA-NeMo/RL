# General ModelOpt Real-Quant Refit Implementation Plan

This plan implements
[General ModelOpt Real-Quant Refit](modelopt-general-real-quant-refit.md).
Real-quant KV-cache work remains deferred until this plan is complete.

The initial acceptance set is ModelOpt NVFP4 W4A4 and W4A16. Interfaces remain
format-neutral, but another format is deferred if it requires a special
MBridge or NeMo RL workaround.

## Branches

Use `mxin/modelopt-real-quant-refactor` from the latest `origin/main` in each
repository that changes:

- TensorRT-Model-Optimizer;
- Megatron-Bridge;
- NeMo RL; and
- vLLM only when characterization exposes a native reload defect.

Do not pin downstream repositories to development commits until the upstream
change they need is published or a temporary review branch is explicitly
selected.

The implementation dependency order is strict:

```text
ModelOpt pure export API
  -> Megatron-Bridge distributed conversion
  -> vLLM native reload fixes, only where characterization requires them
  -> NeMo RL orchestration cleanup
```

## Phase 1: Freeze reference behavior

1. Select small fixed modules covering scalar, per-channel, per-block, and
   mixed per-layer quantization state.
2. Export each module with ModelOpt's current HF exporter and archive the
   tensor keys, shapes, dtypes, and values as test-time references generated by
   the test itself.
3. Record the native vLLM ModelOpt paths for NVFP4 W4A4 and W4A16 and the gaps
   currently covered by NeMo RL adapters.
4. Add no promise for other formats. The output is an NVFP4 capability matrix
   and a list of native vLLM gaps.

Gate: the reference tests reproduce current offline exports and distinguish
the supported-format intersection from formats supported by only one side.

## Phase 2: Extract the ModelOpt pure export core

1. Split quantized-weight conversion in
   `modelopt/torch/export/unified_export_hf.py` into a public non-mutating core
   and the existing module-mutating checkpoint adapter.
2. Define an immutable scalar export-state contract for one logical weight.
   Reject formats and quantizers that need structured sidecar state.
3. Move scale derivation, packing, relative output names, and per-layer config
   generation behind the public API.
4. Make the existing resident and streaming HF exporters consume the same
   core.
5. Add unit tests for offline/pure parity, source immutability, repeated export,
   disabled quantizers, and mixed precision.

Gate: all existing ModelOpt export tests pass, and pure output is tensor-for-
tensor identical to the offline exporter for every selected format.

Hard dependency: merge the public ModelOpt API and update the MBridge
development branch to a commit that contains it before starting Phase 3. Do
not add a temporary copy of the export logic to MBridge or NeMo RL.

Review checkpoint: the persistent reviewer checks that the public API is
format-neutral and smaller than exposing existing exporter internals.

## Phase 3: Generalize Megatron-Bridge export

1. Replace MBridge's NVFP4 `QuantMeta`, scale derivation, and `quant_mode`
   dispatcher with ModelOpt export state.
2. Max-reduce scalar amax values over TP, copy them to every HF projection
   produced from the source weight, and keep expert states separate through
   PP/EP conversion.
3. Invoke ModelOpt packing only after a weight and its sidecars have canonical
   HF layout.
4. Generate the deployment quantization config from canonical per-layer
   records and expose it separately from the lazy tensor iterator.
5. Emit the same canonical names as ModelOpt's normal export for the target HF
   architecture. Do not add a NeMo-specific fused payload schema.
6. Keep export streaming and bounded-memory behavior.

Gate: MBridge output matches ModelOpt offline HF output for TP1/TP2, Megatron
policy EP1/EP2, dense, fused QKV/gated MLP, sequential MoE, and grouped MoE
cases selected in Phase 1. An instrumented iterator test must also prove that
conversion and consumption are lazy rather than materializing the full
canonical checkpoint; an integration measurement must show that conversion
memory is bounded by active conversion tasks, not total model size.

Review checkpoint: re-review distributed reduction semantics, mapping axes,
and peak memory before downstream integration.

## Phase 4: Characterize and fix native vLLM refit

1. For the native vLLM ModelOpt NVFP4 W4A4 and W4A16 paths, load the offline
   checkpoint normally and capture deterministic outputs and runtime tensor
   metadata.
2. Construct the same model with dummy weights and send the canonical tensor
   stream through vLLM 0.25.1's public `init/start/update/finish`
   weight-transfer transaction.
3. Repeat after a controlled source-weight change and verify output change plus
   stable runtime tensor addresses.
4. Run the transaction tests with both IPC and NCCL transports. Test dense,
   routed-MoE, and Mamba/hybrid alias-buffer behavior. Keep full
   expert ownership on every vLLM rollout rank in this first landing; native
   vLLM rollout EP refit is a separate follow-up.
5. Fix failures behind vLLM's public weight-transfer update API. Do not call
   private reload helpers or add a copied quantization method in NeMo RL.

Gate: disk load and public IPC/NCCL online refit are equivalent, and a second
refit is correct for every format/model class claimed by the capability matrix.
Inject an update failure after `start_weight_update`; the current engine must
be discarded, and a reconstructed engine must accept a complete successful
refit. Reusing a failed engine is not supported.

If no vLLM code changes are needed, record that result and do not create a
vLLM branch merely for documentation.

Hard dependency: every native vLLM gap covered by a current NeMo compatibility
adapter must either be proven absent or fixed upstream and included in the
pinned vLLM dependency before Phase 5 deletes that adapter.

## Phase 5: Simplify NeMo RL

1. Add a policy API that returns the MBridge-generated deployment config.
2. For `generation.real_quant: true`, initialize the policy before
   vLLM model loading and pass its config through HF overrides.
3. In colocated mode, capture the config, offload the policy, let vLLM size and
   allocate against the policy-free GPU, then restore the policy before the
   initial refit or training operation.
4. Let vLLM select its native ModelOpt quantization method.
5. Send the canonical iterator through vLLM's public
   `start_weight_update`/`update_weights`/`finish_weight_update` transaction.
6. Remove each W4A4/W4A16 mode resolver, hand-built vLLM config, custom ModelOpt
   vLLM quantization class, or fused-MoE payload rewrite only after its Phase 4
   replacement gate passes against the pinned vLLM dependency.
7. Remove generation-side ignore/mode configuration that is now derived from
   the initialized policy.
8. Preserve fake-quant, BF16, and non-vLLM paths unchanged.
9. Update to the latest compatible ModelOpt pin and regenerate dependency lock
   files with the repository-supported tooling.

Gate: focused unit tests cover startup ordering, descriptor propagation,
manifest mismatch, and delegation to native vLLM loading without asserting
format-specific details. A failed transaction marks the engine unusable and
forces reconstruction before the next operation. Source checks verify that
NeMo RL does not import vLLM's private layerwise-reload modules, cache reload
roots, or manipulate quantization-method kernel state.

Review checkpoint: re-review the aggregate deletion and ensure NeMo RL owns
only orchestration, transport selection, and validation.

## Phase 6: End-to-end validation

1. Run the relevant unit and lint suites in each changed repository.
2. Run dense real-quant smoke tests for W4A4 and W4A16.
3. Run Qwen3-30B-A3B MoE and Nano3 hybrid smoke tests with two refits, one
   generation, and one training step.
4. Compare online refit with offline ModelOpt export using fixed prompts and
   deterministic decoding.
5. Verify policy parameters, quantizer state, and optimizer-visible objects are
   unchanged by export.
6. For colocated mode, record startup peak memory and verify the policy can be
   restored after vLLM allocation under the unchanged memory configuration.
7. Record refit latency and peak memory against the existing NVFP4 path. Treat
   a major regression as a blocker even when parity passes.

Gate: all correctness checks pass, loss is finite and nonzero where expected,
and no format-specific NeMo RL branch is required for the tested formats.

## Phase 7: Migration and cleanup

1. Update examples and the real-quant architecture guide to describe the
   policy-derived deployment descriptor.
2. Remove obsolete tests that only validate the deleted hand-built W4 modes;
   retain behavior and parity tests.
3. Update ModelOpt, MBridge, and optional vLLM pins through normal merge commits.
4. Run the final NeMo RL CI subset and one clean end-to-end smoke from the
   merged pins.
5. Only then revise the real-quant KV-cache design to use the generalized
   descriptor and canonical tensor stream.
6. Document the intentional removal of private real-quant mode names and
   duplicated generation recipe fields; do not add compatibility aliases.

## Stop conditions

Stop and revisit the design rather than adding downstream helpers when:

- the pure ModelOpt exporter cannot match offline export without mutating the
  policy;
- a sidecar cannot be represented by the agreed logical layout contract;
- vLLM requires a NeMo-only checkpoint schema;
- a format needs a second independent recipe parser in NeMo RL; or
- repeated refit cannot preserve runtime storage required by CUDA graphs.
