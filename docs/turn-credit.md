# Agentic turn credit on the replay branch

This branch ports Jiaqi's turn-judge feature onto `binhu/ppo-swe-reply`
(`988397ff6`). Source: `jiaqiz/nt4-turn-judge` at `9f00e26ba1` and Gym
`jiaqiz/turn-judge-service` at `0c7d6b994`. The matching Gym branch is
`binhu/turn-judge-service`. Existing PPO branch replay is retained, not replaced.

## Method

After all siblings finish, a separate agentic judge reads their patches, tests,
and trajectories. It identifies separating decisions, compares passing/failing
pairs, and labels model calls good (+1), harmful (-1), or unlabelled (0).
No new student continuation is generated by this feature.

For a rollout with scalar GRPO advantage A, the trained-token-weighted mean label
is jbar. The new token advantage is

`a_t = A + min(lam, kappa / max(abs(j-jbar))) * abs(A) * (j_t-jbar)`.

The shift sums to zero within each rollout and cannot change its advantage sign.
Unlabelled, all-equal-label, zero-advantage, and unproven-alignment rows retain
plain GRPO. `lam=0.5`, `kappa=0.8` are upstream defaults, not Nano-tuned values.

## Enable on a Nano GRPO experiment

Use `examples/run_single_controller.py` and your existing Nano policy, data,
OpenCode environment, parallelism, sampler, and loss settings. Merge the fragment
in `examples/configs/turn_credit.yaml` into that configuration. It is not a
standalone model/cluster recipe. Set the two endpoint paths for your deployment.
Do not copy N4 model settings or AGA node counts.

Required: Gym OpenCode sandbox rollouts, token capture enabled, segment rows
disabled, no compaction or subagents, and multiple generations per prompt.
Mixed-outcome groups provide the signal; GPP=1 cannot do this comparison.
Use the same GPP for baseline and treatment.

Supported experiments:

- Plain GRPO: `grpo.turn_credit.enabled: false` (default).
- Shadow judge: `enabled: true`, `apply: false`; measures labels/coverage with no shaping.
- Turn credit: `enabled: true`, `apply: true`.
- Position control: also set `shuffle_within_rollout: true`; defaults to size-matched shuffling.
- Positive-only or negative-only: `shape_rollouts: passing` or `failing` (uses sign of A).

This does **not** combine the judge with PPO/GAE or the critic-based replay
selector. PPO, OPD, advantage clipping, reward penalties, and competing per-turn
advantage hooks are rejected when turn credit is enabled. Existing PPO replay
experiments continue to run with the feature disabled.

## Service and data contract

Start Gym's `resources_servers.turn_judge.service` separately; see its README.
`judge.endpoint_file` contains `export TURN_JUDGE_URL=http://host:port` for that
HTTP service, **not** the model server. The service has its own `--endpoint-file`
with `JUDGE_BASE_URL` and `JUDGE_MODEL_NAME` for the judge model.

The service needs read access to the rollout artifacts at the paths reported by
Gym, task images, answer keys, OpenSandbox configuration and OpenCode assets.
Use shared mounts with identical paths. The included labeling rules are portable;
model weights, sandbox infrastructure and OpenCode binaries are not bundled.

Judging is awaited after group seal, before the group becomes training-ready.
It adds latency and judge compute. A timeout, missing payload, or transport failure
falls back to plain GRPO. Shaping requires exact per-call token-count agreement;
an ambiguous mapping is dropped rather than assigning labels to the wrong tokens.

Full checkpoints preserve labels and in-flight judge payloads in
`turn_judge_state.pt`; the recovery ledger preserves per-sibling turn metadata.
Old checkpoints without either optional field remain readable. Replaying labels
requires the same algorithm configuration and matching rollout identities.

## Metrics and verification

Watch `turn_judge/*` for service status, skipped groups, latency and failures;
`turn_credit/shaped_row_share`, `labeled_token_share`, `mass_moved_share`, and
`drop/*` for effective coverage. `sign_flips` should be zero and
`zero_sum_max_err` should remain at floating-point noise. Reward alone cannot
show whether this feature actually applied.

CPU tests cover shaping invariants, alignment, HTTP coordination, timeout/restart
and mocked service execution. They do not validate live Nano training, judge
quality, sandbox deployment, or GPU throughput. Run a real-model smoke before
using this branch for a formal experiment.

Migration checks (local CPU environment, Python 3.12): 48 feature tests, 58
recovery tests, 233 controller/config/lifecycle checks, and 37 Gym service/export
tests passed. Four external-archive tests were skipped. Eight controller fixture
failures and one existing config-reference mismatch also reproduce on the
unmodified `988397ff6` baseline; this port does not fix those unrelated failures.
The three new RL modules pass the repository's Pyrefly checker. No live model
or cluster smoke was run during the migration.
