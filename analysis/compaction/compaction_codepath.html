2. What compaction does inside OpenCode

2a. When it fires

After every finished assistant turn the loop calls compaction.isOverflow with that turn's reported usage (session/prompt.ts L1492-1499). The check (session/overflow.ts L19-26) is:

count  = prompt_tokens + completion_tokens            (vLLM usage of the LAST turn; _mapUsage, language-model.ts L689-703)
usable = model.limit.context − maxOutputTokens(model)   (limit.input is not set for the nemo-gym model)
fire   = count ≥ usable

The bench CLI registers the model as {context: OPENCODE_CONTEXT_LIMIT, output: max(1000, context/4)} (bench/cli.ts L213-215). With the launch script's 131072 that is context 131072, output 32768, so compaction fires at ≈98 304 tokens, not at 131 072. The --context-limit knob was written as a testing knob (its docstring says so), but the production config routes through it.

Requests carry no max_tokens (language-model.ts L536-541), so vLLM lets a single turn generate up to max_model_len − prompt = up to ~98k tokens when the prompt is at the compaction threshold. The 196 608 max_new_tokens in the yaml is never sent on this path.

2b. The summary call

session/compaction.ts L346-470. The same policy model is called (agent "compaction" has no model override, so it falls back to the session model) with:

  • the head of the history (everything except a recent tail, see 2c), rendered with media stripped and tool outputs truncated to 2 000 chars (TOOL_OUTPUT_MAX_CHARS, L38, L408-411). But that is not what the model actually sees: the head's last assistant still carries its token IDs, the provider attaches them (language-model.ts L490-504), and the vLLM proxy replaces the rendered prefix with the original token stream. The summary call therefore sees the original SWE system prompt with tool definitions, the untruncated history, and then only the summary-request message. The compaction agent's own system prompt is never seen. Since the request carries no tools, a tool call emitted here is not parsed, stays as text, becomes the "summary", and is flagged is_invalid_tool_call (−5 advantage);
  • a user message with the fixed SUMMARY_TEMPLATE (Goal / Constraints / Progress / Key Decisions / Next Steps / Critical Context / Relevant Files, L43-78), or an "update the anchored summary" variant if there was a previous summary (L124-135);
  • tools: {} and system: [], and the request header x-turn-kind: compaction which the provider reads to tag the turn (language-model.ts L222-239).

The summary is stored as an assistant message with summary: true. Then a synthetic user message "Continue if you have next steps, or stop and ask for clarification if you are unsure how to proceed." is appended (L528-556, metadata.compaction_continue).

2c. What the model sees after compaction

message-v2.ts filterCompacted (L1083-1134) is designed to rebuild the visible history as [compaction user msg "What did we do so far?", summary assistant msg] + tail (verbatim recent turns) + continue msg. The tail is selected by compaction.select (compaction.ts L247-296): the last tail_turns (default 2) user turns that fit in preserveRecentBudget = min(8000, max(2000, 0.25·usable)) = 8 000 estimated tokens.

In this run no tail survives. The size estimate is Token.estimate(JSON.stringify(toModelMessages(...))) (compaction.ts L239-245, chars/4), and the model messages carry every assistant's providerOptions with its full prompt_token_ids / generation_token_ids / generation_log_probs arrays. Near the ~99k trigger the last assistant alone serializes to hundreds of thousands of characters, so splitTurn never finds a slice under budget and tail_start_id stays undefined. The post-compaction context is therefore system prompt + "What did we do so far?" + summary + "Continue…" and nothing from the recent turns. (A SWE session has a single user turn, so "2 turns" would otherwise mean "the last few assistant steps".)

The provider deliberately attaches no token IDs on the first post-compaction request (language-model.ts L477-508, is_compaction_turn guard), so the vLLM server re-tokenizes the compacted message list from the chat template. From then on, turns in the new segment again splice exact token IDs. The per-segment step budget is reset (stepsSinceCompaction = 0, prompt.ts L1487-1488), so agent_max_turns: 300 bounds each segment, and only the 3 600 s wall-clock timeout bounds the whole rollout.

2d. Segment tagging

language-model.ts _nextSegment (L206-220): a compaction turn bumps segment_index and is tagged compaction; the very next non-compaction turn bumps it again and is tagged post_compaction. Every turn writes a cumulative JSON dump (messages so far, token IDs, log-probs, session_id, segment_index, segment_boundary_reason, turn).

Gym groups the dumps by (session_id, segment_index), keeps the most recent cumulative file per group, and stamps prefix_message_count = message count of the group's first turn (app.py L2486-2537). run() then emits messages[prefix_message_count:] as each segment's trainable output (L3907-3916), so the resent history in the compaction prompt is not double-counted as generation. Segments are sorted by (session_id, segment_index) (L3942); with subagents disabled in practice, trace 0 is always the pre-compaction segment.

Each segment becomes one NeMoGymResponse in responses and one training row (nemo_gym.py L279-294). All rows of a rollout share the same full_result dict and therefore the same reward (binary resolved, app.py L3953).

4. How training consumes the traces

  1. Batch shape. A step needs exactly 64 × 16 = 1024 unique rollouts (grpo.py L5286-5297); the trace row count varies. Group id = position of the prompt group in the step; rollout id = group·16 + rollout_local_idx (L5209-5228).
  2. Masks. loss_multiplier → zeroed for env mask_sample (L5379-5395) → sample_mask. token_mask = 1 only on assistant tokens that carry generation_logprobs (L5401-5412). Later, seq_logprob_error_threshold: 2 zeroes any trace whose mean per-token exp|logp_gen − logp_train| exceeds 2 (L3346-3484).
  3. Advantage. One reward per unique rollout id → GRPO leave-one-out, std-normalised, clipped to ±50 → broadcast to every token of every sibling trace (L5823-5885). Rewards of masked rollouts (timeouts, max-turn, OOM, empty) are still in the baseline.
  4. Loss. force_on_policy_ratio: true makes the PPO ratio identically 1 (loss_functions.py L366-371); ratio_clip_min/max are dead config. The effective per-token gradient weight is advantage × clamp(exp(logp_train − logp_vllm), 0.2, 5) (L421-462), normalised by the global number of valid tokens. This is REINFORCE with truncated importance sampling, not PPO.
  5. One optimizer step per rollout batch. When the trace count ≠ 1024, gbs is set to the padded trace count so the whole batch is one update (L6009-6024). This is required for force_on_policy_ratio to be valid.
  6. Staleness. A rollout is stamped with the weight version at spawn (async_utils.py L960, L1020) and targeted at version+1. Long rollouts keep running through in-flight weight updates; the recorded age never reflects that.

5b. Training-dynamics risks (candidates for the reward rise-then-drop)

#FindingCheck in W&B now
R1 riskMasked terminal states are in the baseline but get no gradient, and compaction removed every other stop. agent_max_turns: 300 resets per segment (prompt.ts L1487-1488); compaction removes the context-window stop; the only rollout-wide bound is the 3 600 s wall clock. A timeout kills the bench before output.jsonl is written, so eval is skipped and reward is 0 even if the working-tree patch was good, and the rollout is masked. Its reward stays in the leave-one-out baseline (advantage_estimator.py hard-codes valid_mask=ones), so siblings that stopped early are penalized while "keep going" never is. As the policy gets longer, timeouts rise and the measured reward falls with nothing pushing back. Prime suspect.swe_agents_train/agent_timed_out/mean, swe_agents_train/patch_exists/mean, multi_trace/fully_masked_rollout_fraction rising while total_reward/mean falls; turns_per_sample/mean, gen_tokens_per_sample/mean, traces_per_sample/mean, trajectory_duration_s/p95 climbing.
R2 riskCompaction fires at ~99k, not 131k, and throws away all recent context. OPENCODE_CONTEXT_LIMIT_TOKENS=131072 is byte-identical to the fork default (no-op). Within a segment every prior turn's reasoning tokens are re-fed verbatim, so verbosity growth under RL accelerates compaction; each compaction replaces working state with a summary and no tail (2c). Half of the 196k vLLM window is never used by the agent.traces_per_sample/mean and /max, multi_trace/traces_per_rollout_mean, multi_trace/mean_trace_length. Needs the proposed reward-by-compaction-count split to attribute.
R3 riskNo trust region and no format guard. force_on_policy_ratio makes the PPO ratio identically 1 (clip 0.2/0.28 inert), reference KL is 0, lr is constant. The only guards are the TIS clamp and the −5 tool-call override, which is applied after the ±50 clip and is larger than any normalized advantage in a 16-rollout group (max ≈ 3.9). Malformed thinking is unguarded (B2).approx_entropy trend, tis_clipped_fraction, is_oob_ratio, sampling_importance_ratio; count of "Setting negative advantage" stdout lines per step (no metric exists).
R4 riskseq_logprob_error_threshold: 2 is an outlier kill switch. The statistic is the arithmetic mean of exp|Δlogp| over a trace; one token with |Δ| > ln(N+1) (≈10.8 nats at 50k tokens) zeroes the whole trace, whose reward still counts in the baseline. Long traces are the likeliest to contain such a token.num_masked_seqs, masked_correct_pct vs batch success rate, max_seq_mult_prob_error vs mean_seq_mult_prob_error gap, multi_trace/masked_trace_fraction.
R5 riskStale KV across in-flight refits, invisible to the age metric. Refit does not drain, recompute_kv_cache_after_weight_updates: false, and nothing else ever resets the prefix cache (validation never runs). A rollout straddling a refit continues on KV from weights v under weights v+1. The weight version is stamped at spawn and target is v+1, so avg_trajectory_age is identically 1.token_mult_prob_error, gen_kl_error, policy_kl_error trending up with multi_trace/mean_trace_length.
R6 riskToken-level normalization plus unbounded length. A rollout's gradient share is its generated tokens summed over all traces; compacted (often failing) rollouts can carry several times the mass of a clean one. train_global_batch_size is inert in multi-trace steps (gbs = trace count, one optimizer step).Correlate gen_tokens_per_sample with total_reward; global_valid_toks.
R7 riskTIS 'tis' type applies the 0.2 floor too (two-sided clamp [0.2, 5], deliberate per 980886e8d but the config comments say max-only). Non-finite ratios are mapped to 0 and then lifted to 0.2 instead of dropped.is_oob_ratio counts both sides; no split exists.
R8 riskOther Gym-side reward plumbing. (a) A sticky context_window marker masks a rollout that overflowed at 196k and then recovered via compaction, rare here. (b) A non-zero OpenCode exit for a non-terminal reason discards the already-captured patch and trains the partial trajectory as an unmasked reward-0 sample. (c) A continuity-assert or NaN in one rollout aborts the whole rollout batch worker, retries it three times, then drops it.swe_agents_train/eval_timed_out/mean; grep logs for "Error in prompt group worker", "Non-contiguous messages found!".

5c. Launch-script and ops risks

  • Run identity. EXP_SUFFIX omits LR, data path, model path, precision recipe and positional overrides. A relaunch with any of those changed resumes the previous checkpoint, optimizer state, dataloader position and replay buffer under the same W&B name and Slurm singleton chain. The code snapshot is also reused if the directory exists, so edits to nemo_rl/ or the yaml are not deployed on relaunch. A reward curve that rises then drops is exactly what a resume with a changed LR or data mix looks like. Check the driver log for a non-null resume checkpoint and whether the first logged step is > 0.
  • Gym is mounted live from another user's checkout (NRL_GYM_DIR default), not from the snapshot or the local submodule, and is silently skipped if absent. The Gym revision actually trained with is not logged.
  • Secrets committed: a W&B API key and a GitLab PAT are literal defaults (L151, L516) and the PAT is written to driver_command.sh / <jobid>-run-cmd.sh. Rotate them.
  • cluster.segment_size=2 is hardcoded on the command line while the yaml says 16 and the comment says they must match; the "default to 16" branch is dead. Validation gets no compaction override (moot: val_period is effectively infinite). checkpoint_must_save_by leaves ~34 min minus setup time before walltime; ft_save_period: 1 already saves every step.

5d. Things to be aware of

  • The compaction summary is a trained single-turn trace (~90k-token prompt, ~1-2k generated) with the rollout's advantage. The tail summary "What did we do so far?" and "Continue…" scaffolding are prompt-only in the next segment. Credit assignment is otherwise clean: no double counting.
  • trace_in_rollout_idx == 0 may be a subagent segment, not the main session: OpenCode session IDs are time-descending, so later subagent sessions sort first. Harmless today because rollout-scoped logic reads the shared full_result, but "representative trace" in the design doc is not what the code selects.
  • mean_prompt_length and total_tokens_per_sample are inflated by the compaction segment, whose prompt embeds the whole pre-compaction context. truncation_rate tests exact equality with 196608 and is ~0 always; natural_termination_rate is ~1 always.
  • Leave-one-out with per-sample std: a lone success in a group of 16 keeps an unnormalized +1.0 (its peers have std 0) while the 15 failures get −0.26 each; two successes give +3.6 / −0.38.
  • With env.should_log_nemo_gym_responses: true the per-trace training jsonl dump (advantages, seq error, masks) is skipped (grpo.py L6377), and the full-result W&B table is commented out, so nothing per-trace is persisted from the trainer.
  • The prefix-replacement hook overrides vLLM's private OpenAIServing._preprocess_chat; newer vLLM (0.20) routes through a different method, so a container bump can silently disable the splice.

7. If I had to bet on the reward drop

  1. R1 (masked timeouts, unbounded turns). First thing to plot: swe_agents_train/agent_timed_out/mean and multi_trace/fully_masked_rollout_fraction against total_reward/mean. If they rise together, the fix is to stop masking agent_timed_out (train it as a failure) or add a session-wide turn/compaction cap so long rollouts end in a trainable state.
  2. Run identity (5c). Rule this out first because it is cheap: was the run relaunched, and did LR, data or code change?
  3. R2 + B3 + B4-today (compaction quality). Needs the reward-by-compaction-count split; if compacted rollouts are the ones collapsing, fix the compaction call's prompt (B3) and restore the tail (B4).
  4. R3 + B2 (format drift with no guard). Cheap to check via the invalid-tool-call count and a think-tag violation rate.
  5. R4 + R5 (staleness and the error gate). Check num_masked_seqs and masked_correct_pct; if the gate is masking a growing, reward-skewed share, switch to a robust statistic or token-level dropping, and A/B recompute_kv_cache_after_weight_updates: true.
