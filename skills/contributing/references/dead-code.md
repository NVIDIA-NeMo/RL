# Dead code

What a change must not leave behind: code nothing uses any more.

- **Do not leave dead code. Dead code is a named thing that exists to be consumed and has no production consumer: a function, method, class, config key, metric, dataclass field, parameter, or unread return value.** It covers both a symbol that lost its last caller in this diff and a new symbol nothing reads. A test-only caller does not count as a consumer. Source: [dead-code-repo-wide-check](../../review-pr-team/references/details/dead-code-repo-wide-check.md).
- **Before deleting something as dead, grep the whole repo at the PR head, not the diff, and check indirect access (`getattr`, `hasattr`, `vars`, string dispatch, `spec=`) and whether it is part of an ABC or interface another backend implements.** A search of the changed files misses callers in files the PR never touched. Source: [dead-code-repo-wide-check](../../review-pr-team/references/details/dead-code-repo-wide-check.md).
- **Treat every name the diff removes as a work list: grep each one at the head.** Callers removed but the definition kept is dead code; a test removed but its name still in a registry (a `--deselect` entry) fails silently; an ABC declaration removed and kept only on the concrete class is a contract downgrade. Source: [diff-removals-are-a-work-list](../../review-pr-team/references/details/diff-removals-are-a-work-list.md).
- **When a refactor removes a no-op at one call site, check the sibling call sites for the same no-op.** The cleanup usually means the operation was a no-op everywhere.
- **When you remove or rename a config key, or change the shape a key accepts, add a check to `nemo_rl/utils/outdated_config_checks.py` so a stale user config fails at startup with the migration to apply.** Without it the old key is silently ignored or fails hours into a run. Details: [removing-outdated-config](details/removing-outdated-config.md).
